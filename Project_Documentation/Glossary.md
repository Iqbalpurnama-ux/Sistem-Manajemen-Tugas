# Glossary (Daftar Istilah)

Daftar istilah dan akronim teknis yang digunakan dalam dokumentasi Project BesokAja. Ditujukan untuk mempermudah anggota tim non-teknis, QA, atau pemangku kepentingan (stakeholder) memahami isi dokumen.

| Istilah | Definisi / Penjelasan |
|---|---|
| **App Router** | Paradigma terbaru dalam Next.js (versi 13 ke atas) di mana komponen secara *default* di-*render* di server. |
| **Baileys** | Pustaka (*Library*) pihak ketiga tidak resmi untuk menghubungkan aplikasi dengan WhatsApp Web tanpa API Resmi. |
| **Claymorphism** | Gaya desain antarmuka pengguna (UI) modern yang menonjolkan elemen 3D bulat, tebal, pastel, dan empuk seperti tanah liat (*clay*). |
| **Cron Job** | Penjadwal (*Scheduler*) yang menjalankan skrip/kode secara otomatis pada waktu tertentu (misal: setiap jam 08:00 WIB). |
| **Edge Functions** | Fungsi peladen (*serverless function*) ringan yang dijalankan di wilayah CDN terdekat dengan pengguna (minim latensi). |
| **Magic Link** | Metode masuk (Login) tanpa *password*, di mana pengguna mengeklik tautan verifikasi yang dikirimkan ke email mereka. |
| **MoSCoW** | Metode prioritisasi fitur: *Must have* (Wajib), *Should have* (Penting), *Could have* (Bagus jika ada), *Won't have* (Tunda dulu). |
| **MVP (Minimum Viable Product)** | Versi awal dari produk yang memiliki fitur sekecil/sesedikit mungkin tetapi sudah bisa memberikan nilai (*value*) utama kepada pengguna dan memecahkan masalah. |
| **OAuth** | Standar terbuka untuk izin otentikasi (misalnya fitur *Login with Google*). |
| **pg_cron** | Ekstensi pada basis data PostgreSQL yang memungkinkan penjadwalan query dan fungsi SQL langsung di dalam database. |
| **RICE** | Metode prioritas (*Reach, Impact, Confidence, Effort*) untuk mengukur seberapa layak sebuah ide/fitur dikerjakan. |
| **RLS (Row Level Security)** | Mekanisme di PostgreSQL untuk membatasi baris data (Row) mana saja yang boleh dibaca/ditulis berdasarkan identitas (Token/User ID) pemanggil query. |
| **Server Actions** | Fitur Next.js yang memungkinkan eksekusi kode *backend* (mutasi database) dipanggil secara mulus dari interaksi tombol atau form di klien (UI). |
| **Serverless** | Model eksekusi *cloud* di mana penyedia (seperti Vercel) secara dinamis mengalokasikan *resource* hanya saat kode dipanggil. Pengembang tidak perlu merawat server / OS. |
| **Soft Delete** | Penghapusan data dengan cara menyematkan tanggal hapus (deleted_at), bukan benar-benar menghapusnya dari cakram keras (Hard Delete). |
| **Supabase** | Backend-as-a-Service (BaaS) *open source* alternatif Firebase, yang didasarkan pada ekosistem PostgreSQL murni. |
| **Vercel** | Platform *cloud* penyedia infrastruktur penempatan (*deployment*) spesifik untuk ekosistem *frontend* modern (Next.js). |
| **Zod** | *Library* TypeScript untuk mendeklarasikan dan memvalidasi struktur data (schema validation) agar tidak terjadi data *error* / injeksi dari sisi pengguna. |
